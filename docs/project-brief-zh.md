# MiniCloudKV：書審專案摘要（截至 2026-09-25）

我以三節點 Key-Value Store 探索「節點會當機、網路會分區時，一筆寫入何時能被安全地回覆成功」。專案使用 Python 標準函式庫實作 Raft 的任期與投票持久化、依照日誌新舊程度投票、領導者選舉、日誌複寫、衝突後綴修復與多數節點提交。每個節點將任期、投票、日誌和提交位置以原子替換及 fsync 儲存；重啟時只重播已提交的操作。為避免分區期間讀到舊資料，讀取也必須提交一筆非修改性的日誌紀錄。

我設計三個真實 HTTP 行程的整合測試：寫入成功後殺掉領導者，確認新領導者仍能讀出資料，並確認舊節點重啟後追上；另以雙向阻斷 RPC 隔離原領導者，驗證它不能確認缺乏多數同意的寫入。我也實作小型線性一致性檢查器，對單一鍵、至多 16 筆已成功完成的操作，搜尋是否存在符合實際先後順序的序列執行。

目前九項自動測試通過。一次本機實測中，殺掉領導者到新領導者首次成功讀取既有值約 402.4 毫秒；100 筆循序 PUT 的單次測量為 351.63 ops/s，p50 2.152 毫秒、p99 14.105 毫秒。這些數據只代表該次容器環境的觀測，尚未支持效能提升的主張。

目前每次狀態變更都重寫並同步儲存完整 Raft 狀態，成本會隨日誌變長。下一步是實作可追加的 WAL、快照與 group commit，建立相同硬體及工作負載下的對照實驗，分析可靠性、吞吐量與尾端延遲的取捨。專案程式、可重現指令、測試及限制均在倉庫中。
